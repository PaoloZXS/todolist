Voglio che tu generi un progetto completo per una PWA chiamata “GeoList”.

NOTA OPERATIVA CACHE PWA
- Ad ogni push/deploy che tocca frontend o asset statici (HTML/CSS/JS/manifest/icone), incrementare sempre la versione in service-worker.js:
  const CACHE_NAME = "cose-da-fare-cache-vX";
- Esempio: v3 -> v4.
- Obiettivo: forzare refresh corretto su mobile ed evitare cache vecchia.

OBIETTIVO
Creare una Progressive Web App installabile (scaricabile come app) che permetta a più utenti di:
- registrarsi o fare login
- essere riconosciuti in tutte le pagine
- vedere una lista unica di “cose da fare” inserite da tutti gli utenti appartenenti alla stessa Azienda/Famiglia
- aggiungere nuove cose da fare
- creare attività private visibili solo all’utente che le ha inserite
- modificare e cancellare solo le proprie voci (i todo privati restano esclusivi)
- spuntare come FATTA/DA FARE qualsiasi voce in lista
- vedere le cose FATTE spostate automaticamente in fondo e sottolineate
- sincronizzare automaticamente la lista in background e al ritorno in primo piano

STACK TECNICO
- HTML + CSS + JavaScript (senza framework pesanti)
- Ogni pagina deve avere il suo .html, .js e .css separati
- Database: TURSO (usa funzioni JS con placeholder per URL e token)
- PWA completa: manifest.json, service-worker.js, icone, caching offline
- Pubblicabile su Vercel come sito statico

STRUTTURA DEL PROGETTO

REQUISITI FUNZIONALI

LOGIN
- Pagina login.html con username, password e Azienda/Famiglia
- Funzione loginUser() in turso-api.js
- Dopo login, salva l’utente in session.js (localStorage)
- Se l’utente non è loggato, reindirizza sempre a login.html

LISTA COSE DA FARE
Ogni elemento deve contenere:
- data di inserimento
- descrizione
- utente che l’ha inserita
- stato: FATTA / DA FARE

Ogni riga deve avere 3 icone:
- modifica
- cancella
- toggle FATTA/DA FARE

REGOLE UTENTE
- Ogni utente può modificare/cancellare solo le proprie voci
- Ogni utente può creare attività private visibili solo a sé stesso
- Può spuntare FATTA/DA FARE qualsiasi voce

GESTIONE FATTA/DA FARE
- Se FATTA → sottolineata + spostata in fondo alla lista
- Se DA FARE → torna nella parte superiore

COLORI E UI
- Nessun colore rosa, fucsia, giallo
- Palette tecnica: grigi, blu, toni neutri
- Stile moderno, leggibile, professionale

PWA (INSTALLABILE)
Genera:
- manifest.json completo (nome, short_name, icone, colori, start_url, display standalone)
- service-worker.js con caching statico e supporto per refresh corretto su mobile
- registrazione del service worker in index.html
- bottone “📲 Scarica App” che appare quando la PWA è installabile (gestione beforeinstallprompt)

TURSO
In turso-api.js crea funzioni con placeholder:
- loginUser(username, password, groupName)
- getTodos(userId, groupName)
- addTodo(text, userId, isPrivate)
- updateTodo(id, text, actingUserId, isPrivate)
- deleteTodo(id, actingUserId)
- toggleTodoStatus(id, status)

Non inserire token reali, usa:
const TURSO_DB_URL = "INSERISCI_URL";
const TURSO_DB_TOKEN = "INSERISCI_TOKEN";

OUTPUT RICHIESTO
Genera TUTTI i file completi:
- index.html
- login.html + login.js + login.css
- todos.html + todos.js + todos.css
- base.css
- turso-api.js
- session.js
- manifest.json
- service-worker.js
- icone minime (puoi generare versioni base in PNG)
- eventuali helper JS

Il codice deve essere completo, funzionante e pronto da caricare su GitHub e Vercel.
